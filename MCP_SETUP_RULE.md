# Reuse Mesh: типовое правило подключения MCP

Используй это правило, когда пользователь просит подключить Reuse Mesh к AI IDE.

1. Сначала определи AI IDE. Если она неизвестна — уточни её название. До изменения конфигурации задай два коротких вопроса: подключать Reuse Mesh **только к текущему проекту** или **глобально для пользователя**; и где доступен LiteLLM key — имя переменной окружения или путь к локальному секретному файлу.
2. После ответа используй актуальный нативный механизм MCP этой IDE для соответствующей области. Не копируй конфигурацию другой IDE и не проси пользователя вручную выбирать формат, если IDE умеет настроить его сама.
3. Подключай только этот Streamable HTTP endpoint:

   ```text
   https://litellm.ds-hub-cf.ru/reuse_mesh/mcp
   ```

4. Передай LiteLLM key как bearer-токен из переменной окружения или встроенного защищённого хранилища IDE. Не проси вставлять значение ключа в чат и не записывай его в конфигурацию. Если пользователь указал путь к файлу, попроси название переменной окружения, в которую его среда безопасно загружает. Если IDE не умеет безопасно ссылаться на секрет, остановись и объясни ограничение. Если IDE поддерживает пользовательские HTTP-заголовки, используй:

   ```text
   Authorization: Bearer <YOUR_LITELLM_REUSE_MESH_TOKEN>
   ```

5. Никогда не подключай напрямую `teamrepomcp.ds-hub-cf.ru`: это внутренний upstream LiteLLM. Не записывай токен в Git, исходный код, issue или чат.
6. После настройки проверь, что IDE видит инструменты `get_rules`, `list_repositories`, `search_components`, `submit_feedback` и `get_feedback`.
7. Добавь правило Reuse Mesh в нативные постоянные инструкции этой IDE в выбранной области. Для работы с компонентами агент должен сначала вызвать `get_rules`, затем при выборе, сравнении или новой реализации — `search_components`.
