# Централизованный реестр моделей

Навык [`model-usage-audit`](../model-usage-audit/SKILL.md) объясняет по коду, какую бизнес-задачу решает модель в проекте, отдельно исследует саму модель на Hugging Face/у автора и указывает владельца репозитория как ответственного. Он дополняет `reuse-mesh`: поиск готового компонента и анализ фактического применения — разные этапы.

## Что готово

- Пагинированный сбор GitHub-репозиториев и ограниченное чтение default branch с привязкой к SHA.
- Семантический разбор: вход → функция/модель → использование ответа → бизнес-результат. Название репозитория и техническая операция не заменяют такую цепочку.
- Отдельные model profiles: возможности модели, автор, архитектура, лицензия, результат поиска, URL и revision model card. Точное совпадение, алиас и возможная основа различаются.
- Общий HTML-дашборд с бизнес-задачами на первом экране, срезами по проекту/направлению/происхождению и деталями до model card, входа/выхода и кода.
- Отдельные сигналы по отсутствию владельца, revision и lifecycle-проверки; подтверждённые выводы об устаревании требуют первоисточника.
- Сравнение снимков с оговоркой о сопоставимости охвата, экспорт текущего среза и закрытое хранение кэша.

Откройте [публичный пример HTML](model-audit-public.html) после скачивания либо через локальный HTTP-сервер. В GitHub HTML отображается как исходный файл. Данные: [снимок](model-audit-public.json), [семантические проверки](model-audit-public-review.json), [результаты поиска моделей](model-audit-model-lookups.json). В исходном срезе — 14 публичных репозиториев; по коду разобраны 11 применений в 6 проектах. Один класс AST развёрнут в два специализированных checkpoint с разными задачами. Остальные автоматические находки видны отдельной очередью и не считаются завершённым анализом. Закрытые проекты в публичные файлы не включены.

## Проверенные примеры

| Проект | Что найдено | Что действительно установлено |
| --- | --- | --- |
| wolf_sounds_demo | MIT AST и два ASTBasedClassifier | Разметка полевых аудиозаписей: сначала отсечь фрагменты без животных, затем найти вой волка среди оставшихся; конечный результат — метки и интервалы. База найдена на HF; точные специализированные веса там не идентифицированы. |
| mimic_text2video | distiluse-base-multilingual-cased-v1 | Загрузка SentenceTransformer для сопоставления текста и жестовых видеофрагментов через FAISS. |
| VLM_retain_with_SMILES_2025 | Qwen2.5-VL-7B-Instruct | Конфиг с peter_multimodal и код оценки WER указывают на OCR исторических рукописей. Слово SMILES в имени репозитория не было достаточным основанием считать выбранный pipeline распознаванием молекул; прежняя аннотация исправлена. |
| InkSight-tool | Qwen3 route, MiniLM embeddings, optional cross-encoder | Анализ древних арабских рукописей Центральной Азии: embeddings ищут фрагменты, optional reranker уточняет порядок, LLM отвечает исследователю по контексту. Это видно из API → AgenticChatBot → search_knowledge → системного prompt. |
| MAS | PP-OCRv5 mobile/server | Оцифровка строк исторических арабских рукописей. Mobile-модель найдена у PaddlePaddle; точное арабское server-имя не подтверждено поиском. Общая server-модель показана только как возможная основа. |
| animal_classification | EfficientNet B7 | Загрузка ImageNet-весов в тесте фабрики; это не доказательство запуска сервиса. |

Все строки имеют ссылки на конкретный коммит в JSON проверок и дашборде. Для базового AST сверена [model card](https://huggingface.co/MIT/ast-finetuned-audioset-10-10-0.4593), для Qwen — [model card](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct), для текстовых embeddings — [model card](https://huggingface.co/sentence-transformers/distiluse-base-multilingual-cased-v1). Лицензия основы не автоматически определяет лицензию своих весов и данных.

Дополнительно прочитаны cards [MiniLM embeddings](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), [cross-encoder](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2), [арабского PP-OCRv5 mobile](https://huggingface.co/PaddlePaddle/arabic_PP-OCRv5_mobile_rec), [Qwen3](https://huggingface.co/Qwen/Qwen3-235B-A22B) и [официальная документация torchvision EfficientNet B7](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.efficientnet_b7.html). Старое имя cross-encoder перенаправляется на каноническое MiniLM-L6-v2. API exact арабского server-имени вернул 401, публичный поиск — без совпадений: это не доказательство отсутствия модели. Сохраняются оба наблюдения.

В InkSight-tool обнаружен вызов `langgraph.prebuilt.create_react_agent`. [Актуальная официальная документация](https://reference.langchain.com/python/langgraph.prebuilt/chat_agent_executor/create_react_agent) отмечает его deprecated. Вывод: проверить актуальность способа построения агента при обновлении зависимостей. Текущая установленная версия и реальный сбой не проверены; LLM из-за этого не получает статус deprecated.

## Повторный запуск

Требуются Python 3.9+ и GitHub CLI `gh` с уже выполненной авторизацией. Сборщик использует текущие права аккаунта и не создаёт токены. Команды выполняются из корня клона:

```sh
python3 model-usage-audit/scripts/collect.py --org ds-hub-sochi \
  --visibility public --max-files 25 \
  --output .local/model-audit/inventory.json --cache .local/model-audit/cache

python3 model-usage-audit/scripts/render.py \
  --input .local/model-audit/inventory.json \
  --review docs/model-audit-public-review.json \
  --output .local/model-audit/dashboard.html

python3 -m unittest discover -s model-usage-audit/scripts -p 'test_*.py' -v
```

После сбора агент обязан прочитать цепочки вызовов и отдельно исследовать конкретные модели. Например:

```sh
python3 model-usage-audit/scripts/lookup_models.py \
  --model sentence-transformers/all-MiniLM-L6-v2 --search arabic_PP-OCRv5_server_rec \
  --cache .local/model-audit/model-cards --output .local/model-audit/model-lookups.json
```

Скрипт сохраняет metadata и README, но смысловое описание пишет агент после чтения источника. Он не скачивает веса и не запускает исследуемый код. Поиск похожей модели не подтверждает идентичность весов; 401/недоступность не превращаются в «модели не существует».

Для внутреннего аудита `--visibility all` включает доступные закрытые проекты. Храните полный снимок, overlay, HTML и кэш в закрытом каталоге; `.local/` исключён из Git. Без отдельного решения не загружайте их в публичный репозиторий или на публичный хостинг. `--public-only` отфильтровывает репозитории при рендеринге, но не заменяет проверку самого overlay на секреты и закрытые ссылки.

Для показа в браузере достаточно скопировать итоговый HTML в отдельную папку и запустить для неё `python3 -m http.server 8766 --bind 127.0.0.1`; не обслуживайте папку кэша исходников. HTML автономен, не отправляет данные на внешние сервисы. Ссылки на свидетельства открываются только по нажатию.

Overlay является результатом проверки конкретного SHA. После изменения коммита renderer не применит старую проверку: агент должен перечитать соответствующий код и обновить свидетельства. Проверки текущего публичного примера намеренно не считаются вечными.

Для сравнения сохраните предыдущий JSON и добавьте renderer `--previous previous-inventory.json`. Изменение охвата, прав доступа, версии сборщика или лимита файлов не должно интерпретироваться как внедрение/удаление модели.

## Ответственный

Принятое правило: ответственный — владелец репозитория GitHub (`owner.login`). Для текущего набора это организация `ds-hub-sochi`; значение подтверждено списком репозиториев GitHub API. Оно заполняется для всех записей и не требует отдельного ручного назначения. Автор коммита и CODEOWNERS не заменяют владельца; CODEOWNERS можно хранить дополнительным полем.

Overlay хранит `business_task`, вход/выход, `code_trace`, профиль модели и источники. Публичный `teamrepo-rules` содержит навык, формат и публичные примеры; закрытый рабочий реестр хранится отдельно. Для статуса production нужен реальный вызов сервиса, дата, model ID/revision и runtime-свидетельство. Это требование не мешает объяснять бизнес-назначение статического кода.

## Границы пилота и приёмка

Сканирование охватывает только доступные текущему аккаунту репозитории и default branch. Ветки разработки, git submodules, недоступные веса, внешние serving-конфиги, крупные/исключённые файлы и динамические имена могут скрывать модели. Предустановленные каталоги поддерживаемых моделей внутри fork и тестов не доказывают использование всех перечисленных моделей. Поэтому агрегаты кандидатов нельзя использовать как отчёт о закупках, нагрузке или production-парке.

25 регрессионных проверок покрывают сбор, приватность, SHA, ссылку на ячейку, версии проверок, разделение применений, HTML, обязательное основание бизнес-задачи, отдельное описание модели, назначение ответственного по владельцу репозитория, сохранение HF-алиаса и различие ошибки доступа/отсутствия модели. Кроме них при приёмке проверьте реальные фильтры, сброс, пустой срез, ссылки, экспорт и узкую ширину окна. Тесты не доказывают правильность смыслового вывода: её проверяют чтением цепочки кода и model card.

Reuse Mesh в окружении подготовки был сконфигурирован, но его ключ не был доступен; `get_rules`/`search_components` выполнить не удалось. Замена моделей не выполнялась и рекомендации альтернатив не выдавались. Навык сохраняет требование обратиться к Reuse Mesh перед будущими рекомендациями или новой реализацией.
