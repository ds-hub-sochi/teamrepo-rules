# Реестр использования моделей

Создай воспроизводимый реестр «проект → задача → модель → ответственный → свидетельства» и дашборд. Различай найденное упоминание, декларацию команды, загрузку модели в коде, обучение и подтверждённое рабочее применение.

## До старта

Кратко зафиксируй цель, источники/ветки, ограничения доступа, формат результата и точки проверки. Используй уже заданные пользователем условия, уточняй только влияющие на результат пробелы. По умолчанию анализируй default branch и публичные репозитории; включай доступные закрытые репозитории для внутреннего аудита организации, сохраняя результаты в закрытом месте.

Прочитай [контракт и критерии](references/contract.md). Перед новой реализацией или рекомендацией замены соблюдай применимые правила Reuse Mesh из `teamrepo-rules`; недоступность сервиса явно запиши. Сам аудит не требует установки моделей или выполнения исследуемого кода.

## Сбор

Для GitHub используй `scripts/collect.py` (Python 3.9+, авторизованный `gh`). Все пути ниже задавай относительно корня клона `teamrepo-rules`, либо замени их абсолютными путями к установленному навыку:

```sh
python3 model-usage-audit/scripts/collect.py --org ORGANIZATION \
  --visibility public --output .local/model-audit/inventory.json \
  --cache .local/model-audit/cache
```

`--visibility all` включает доступные приватные проекты. `--repo NAME` ограничивает список; флаг повторяемый. Лимиты `--max-files` и `--max-bytes` ограничивают чтение; `--workers` — параллельные HTTP-запросы. Кэш содержит исходники и должен оставаться закрытым. Не запускай скачанные скрипты, ноутбуки и не десериализуй веса.

Сборщик фиксирует SHA, ссылки на строки, выбранные файлы, ошибки и пропуски. Он выдаёт **кандидатов**, а не полный список моделей. Regex не разрешает динамические имена, внутренние API, импорты собственного класса и произвольные архитектуры. `scanned` означает чтение всех подходящих файлов в заданных форматах, не полноту семантического аудита. Отсутствие кандидатов не означает отсутствие моделей.

## Проверка и обогащение

1. Прочитай README, вызовы загрузки и их вызывающий код, конфиги запуска, обучение и метаданные артефактов. Углубляй чтение по неразрешённым именам и пропущенным файлам; фиксируй границы оставшегося покрытия.
2. Объединяй алиасы только по свидетельствам. Backbone, tokenizer, embedding, adapter и конечная модель могут быть разными сущностями. Одна строка — использование одной модели для одной задачи в одном проекте; кандидат до проверки может объединять несколько задач.
3. Для собственных весов установи архитектуру и базовую модель отдельно от происхождения чекпойнта. `best.pt` не доказывает собственное обучение. Для fine-tuning нужны код train/loss/optimizer и связь с артефактом; без неё оставь неопределённость.
4. Владельца модели бери из декларации команды/владельца сервиса. CODEOWNERS даёт владельца кода, commit author — автора изменения; ни один сам по себе не назначает ответственного за модель. Запиши неизвестных отдельно.
5. Сохрани проверенные записи в отдельном JSON overlay по схеме из контракта, с `reviewed_commit`, `review_evidence`, `task`, `owner`, `origin`, `stage`. Сборщик не меняет исходные репозитории. Несовпадение SHA делает проверку устаревшей.

## Устаревание и изменения

Разделяй: подтверждённый lifecycle-риск по первоисточнику; инженерный сигнал для проверки; неизвестное. Возраст репозитория и выход более новой модели сами по себе не доказывают устаревание. Для каждого подтверждённого риска нужны модель/версия, официальный источник, дата проверки, применимость к найденному способу использования и конкретный следующий шаг. Примеры: прекращение API, архив upstream, несовместимость среды или неподдерживаемая версия.

Заполняй `lifecycle` в overlay; не превращай отсутствие такой проверки в зелёный статус. Предложение замены должно учитывать метрику качества, latency, hardware, лицензию и регрессионный тест на тех же данных. Модели автоматически не меняй.

## Результат и повторный запуск

```sh
python3 model-usage-audit/scripts/render.py \
  --input .local/model-audit/inventory.json \
  --review .local/model-audit/review.json \
  --output .local/model-audit/dashboard.html
```

`--review` необязателен. HTML автономный: обзор, покрытие проектов, семейства моделей, очередь проверки, фильтры, детали со ссылками и экспорт текущей выборки. Для публичного примера используй `--public-only`; дополнительно проверь overlay и итог на закрытые названия, ссылки, секреты и данные. Полный закрытый снимок не добавляй в публичный `teamrepo-rules` и не публикуй в Pages/Sites.

При повторном сборе сохрани предыдущий снимок и передай `--previous PATH` в renderer. Добавления/исчезновения сравниваются только при сопоставимом покрытии, успешном чтении файлов и одинаковом SHA для проверки overlay. Исчезновение кандидата при неполном сканировании не означает отказ от модели. Расписание запуска создавай только по запросу.

## Приёмка

- Список репозиториев пагинирован; знаменатель — доступные текущему аккаунту, не все существующие в организации.
- Каждый вывод имеет ссылку на SHA/файл/строку; ноутбук — SHA/номер ячейки без выдуманного номера строки JSON.
- Есть точные лимиты, ошибки, пустые и частично прочитанные проекты; неизвестные не заменены нулями.
- Сводка, фильтры, детали и экспорт согласованы; проверь населённую выборку, сброс, пустую выборку и узкий экран.
- Существующие правила и исследуемые проекты не изменены; команды воспроизведения и ограничения сохранены в `docs` целевого репозитория. В отчёте назови, что проверено и что ещё требует владельца или runtime-свидетельств.
